IMMICH CLONE 0.1.36 - EARLY TEST BUILD

This unsigned prototype is not a validated release. Windows Server 2022 testing
does not establish Windows 10 compatibility. Do not bulk-import a real library yet.

It provides loopback-only access-code login, upload of preserved originals,
JPEG/PNG/BMP/GIF previews, TIFF first-page previews, optional HEIC/video previews,
MP4 browser playback, persistent preview
jobs, browsing, exact original download,
JSON catalog export, and consistent backup/verified restore. Image previews
are limited to 40 megapixels. Uploads are limited to 4 GiB per file. Other formats
are preserved/downloadable but preview failure is shown explicitly. JPEG EXIF orientation, capture date and camera make/model are supported. No advanced camera metadata, server-side folder scanning,
mobile clients, remote sharing or LAN access in this build.

The installer needs administrator permission and uses Windows LocalService.
No .NET, PostgreSQL, SDK, Python, Docker, WSL or separate media codec is required.
Select application data outside cloud-sync folders. Uploaded originals are copied
into this managed data directory. The external source library is not scanned,
changed, moved or deleted. Browser-selected folder import copies files only after
a confirmation showing file count and byte total. Relative folder paths and duplicate source aliases are retained in the catalog
and JSON export. Online-only selections may download when read;
choose only a small available-offline test folder. Uninstall preserves application data and originals.

Start menu: Open library; View access code. Keep the code and backup ZIP private.
Sessions expire after 12 hours and service restart requires signing in again.
The application emits no telemetry and never uploads a machine report.

Backup download stages a ZIP in the data folder before transferring it, so free
space is needed for the full archive. Large downloads should use a browser, not
load into JavaScript memory. Restore only into a new directory, with the service
stopped: immichclone.exe -mode restore -data NEW_ABSOLUTE_PATH -archive BACKUP_ZIP.
Restored previews regenerate. Catalog schema 1 is checked; unknown versions are
refused. JSON catalog export plus independent originals provides a migration path.

Not yet validated: clean Windows 10 install, full OS reboot, long-running
reliability, physical drive disconnect, antivirus/SmartScreen behavior,
production security review and large-library performance. A real full-disk recovery test passed on a disposable cloud NTFS volume. Current startup-failure
rollback covers schema 1, not future schema migrations.

Installer built with Inno Setup (Jordan Russell and Martijn Laan).
Go/x/sys/x/image/bbolt license notices accompany the installed executable.

DIAGNOSTIC BUILD
The app writes private rotating JSON-line diagnostic files under the standard
ProgramData ImmichCloneDiagnostics folder. Each channel retains up to two 4MiB
files (application, offline commands, installer; up to 24MiB total). Events include
UTC time, build version, operation/stage, duration, result/status, transfer byte
counts and error category/native error number. No hardware inventory, OS build,
account/machine names, paths, media names, content hashes, credentials, request
headers/bodies or personal media are logged. No automatic upload occurs.

Use Download diagnostics after signing in, or the Start menu's Export diagnostic
log if the service is unavailable. The exporter lets you save one .log file.
Review and attach it in the private project conversation, not a public issue.
Setup and application data are preserved by uninstall; diagnostic files are also
retained for troubleshooting. Raw Windows/Inno transcripts are not collected.

METADATA/TIMELINE BUILD
JPEG APP1 EXIF orientation (all eight transforms), capture date, camera make/model
are read with bounded parsing. PNG EXIF, GPS, RAW/HEIC/HDR metadata, maker notes and
video capture dates are not supported yet. Original embedded metadata remains
unchanged. Camera date/time is preserved without assuming a timezone; missing
dates fall back to upload date. Existing JPEG/PNG previews are queued once for
rebuilding. Optional fields are additive to schema 1; no original is rewritten.

BMP/GIF/TIFF BUILD
BMP, GIF first-frame and TIFF first-page PNG thumbnails are supported with a
64 MiB encoded-file and 40 megapixel limit. TIFF has a preview viewer only, not
a full-resolution browser viewer. Some TIFF compression/photometric variants
remain unsupported. TIFF orientation/metadata, multipage navigation, HDR and
color-managed rendering are not implemented. GIF full-image viewing uses the
browser; its thumbnail is static. Camera RAW and broader HEIF variants remain unsupported. Originals remain downloadable even when decoding fails.
Previously unsupported assets are reconsidered once; no original is rewritten.

OPTIONAL MEDIA PROVIDER BUILD
Bundled CPU-only FFmpeg 8.1.3 generates thumbnails for tested H.264/HEVC MP4,
rotated MOV and single/grid 8-bit HEIC. Preview decoding is limited to 40MP, a
512 MiB Windows job commitment cap, one process and a 30-second provider deadline.
Preview processing receives a 45-second cancellation budget including checksum
verification; native file reads still depend on storage responsiveness.
High-bit-depth/HDR, RAW, HEIC bursts/advanced metadata and broad camera coverage
remain unverified/unsupported. HEIC/MOV viewers display a derived preview only.
No transcodes or server-side audio playback are generated. MP4 original playback
still depends on the browser's codecs. A missing/failed provider cannot stop
login, upload, native image previews, exact downloads or backups. Use Retry preview
after resolving a failure; cancelled jobs remain queued across service restart.

FFmpeg is used as a separate replaceable executable under LGPL 2.1 or later.
The installed media provider directory includes exact corresponding FFmpeg source,
LGPL and MinGW/compiler notices, configure command, compiler versions, hashes
and build script. It has no network protocols beyond local file/pipe and needs
no separate runtime or GPU package. Provider directories are versioned by binary
hash so executable rollback can retain its previous provider. No user originals
are stored in those program directories. Uninstall preserves the separate library.

VERSION AND VISIBILITY BUILD
The top-right version comes from the running executable, not a hardcoded page
label. Hide from library removes a card from the main grid without deleting the
original, metadata, preview or queued job. Choose Show > Hidden items and Restore
to library to bring it back. Backup, catalog export and original retrieval retain
hidden items. Duplicate uploads do not silently unhide them. This is reversible
visibility metadata, not permanent deletion or source-file removal.

PERSISTENT QUEUE INDEX BUILD
Background work uses a small derived pending-job index rather than scanning all
assets on every timer tick. Catalog asset states remain authoritative. Queue
updates and asset updates commit together; startup rebuilds the index for older
catalogs, restoration and recovery. Originals/export format are unchanged. This
is a worker-efficiency improvement, not proof of bulk-ingestion endurance or a
large-library browsing claim. Full catalog/browser paging is still pending.


PEOPLE AND TAGS PILOT
People & tags provides explicit local analysis of JPEG/PNG/BMP/GIF-first/TIFF-first
photos up to 64MiB / 40MP. A bounded 960px oriented frame is analyzed by an optional
CPU worker with a 512MiB process cap. Select detected faces to name or reassign;
clear a name to leave unknown, undo the last name edit, or mark a missed face.
Suggested matches require confirmation and can be wrong. Custom tags are separate
from the 80-class COCO object suggestions and searchable with filenames/names.
No automatic person merging/naming. False-face dismissal/restore and explicit additive ready-result reanalysis are available; automatic detection replacement remains unavailable.
HEIC/video AI and broad family/age/profile quality are unaccepted. Original bytes
are never changed. Hidden items are excluded from this review page.

Names, manual face boxes and custom tags stay separate from model-owned results
in the private catalog; backups retain all state and restored face crops regenerate
without the AI provider. JSON export includes organization without raw embeddings.
Keep exports/backups private. The native OpenCV/model notices and source/build
provenance accompany the provider. Static runtime fixes require a new worker build.
No Python, SDK, GPU or separate runtime installation is required by the tested
candidate. Original browsing/download remains usable if the provider is missing.
This is a limited pilot, not full recognition accuracy or large-library acceptance.

BULK IMPORT PILOT
Use Bulk import for an explicit managed copy, with saved per-file receipts,
accepted byte/file counts, duplicate counts, pause/cancel and browser-reselect
resume. New previews/AI work wait during active copying; a 60-second lease and
service restart release abandoned pauses. Accepted originals are retained on
cancel. One active copy session, up to 50,000 files per selection, 4 GiB per file.
Empty files are rejected. Resume retransfers accepted files and verifies their
SHA256 receipts; it does not skip on filenames/sizes or resume partial bytes.
Changed content requires a new import. The gallery does not poll during copying.
History is capped at 128 sessions in this checkpoint. Large-library endurance,
paged gallery and large-backup capacity remain unaccepted; start with small tests.

NAVIGATION
People & tags and Bulk import have a prominent Photos & videos Home control.

GALLERY PAGING
The main gallery requests/renders at most 60 items per page. Next/Previous controls
preserve deterministic capture-date, upload-date or case-insensitive filename
ordering, with content-ID ties. Ordering/filter indexes rebuild from the catalog
on open and commit with original/preview/import records. An expired ordering
cursor resets to page one with a notice after a catalog ordering change or service
restart. Later pages are not automatically refreshed; Refresh returns to page one.
The legacy full-list endpoint remains for explicit older/test callers; gallery
polling no longer uses it. People/tag review scalability remains a separate gate.

BACKUP CAPACITY AND PROGRESS
Backups opens a dedicated page with conservative application-storage capacity
planning, background progress/cancel, archive checksum read-back and SHA256.
Completed temporary archives remain for repeated/range downloads until explicit
discard; originals and downloaded copies are not removed. One retained job at a
time. Closing the page does not stop the service job; service restart interrupts
an active job safely. No partial download is published; retry begins anew.
The ZIP format is unchanged and independently restored in acceptance tests.
Archive creation serializes library writes; browsing/status/cancel remain usable.
A complete archive plus snapshot/reserve must fit in application storage, and the
browser download destination needs additional space. No external-destination
picker, incremental backup, automatic retention or full-library acceptance yet.
